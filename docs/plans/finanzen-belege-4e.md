# Finanzen Scheibe 4e: Schnellere Posten-Erfassung, Belegsumme, Artikel, eindeutige Waren – Umsetzungsplan

Folgt auf [finanzen-belege-4d.md](./finanzen-belege-4d.md), gleicher Branch `finanzen-belege-4b` (ein PR für 4b–4e). Wünsche des
Nutzers vom 20.11.2026 nach den 4d-Browser-Checks; Rückfragen beantwortet (Summe ≤ 0 überall erlaubt, Artikel entstehen beim
Buchen), übrige Details hier entschieden.

**Status: umgesetzt** (Phasen 1-5). Abweichungen: Eine Summe genau 0 ist buchbar, ohne Gegenbuchung; Mitglieder können auch Leergut einreichen; die geplante eigene Auslagen-Bilanz auf der Buch-Seite ist nicht umgesetzt (es gibt keinen Endpunkt dafür).

Tabellen und Karten-Maske, Mitglied ebenso.                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Breite                    | `FinanzenBelegPage` nutzt die volle Breite (`maw={1500}`, `FinanzenBelegPage.tsx:394`, entfällt).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Fehler verschieben nichts | Ein Fehlertext unter einem Feld darf Nachbarfelder derselben Zeile nicht verschieben und das Feld selbst nicht anheben. Inputs einer Zeile bleiben auf einer Höhe (auch bei umbrechenden Labels, siehe Ausrichtungsregel). Umsetzung: kleine wiederverwendbare Lösung (z. B. Klasse/Komponente `FeldZeile`, deren Fehlertexte absolut unter dem Input stehen, mit Platz über den Zeilenabstand), angewandt in den Kopfzeilen (`FinanzenBelegPage.tsx:~483`, `~702`), der Karten-Maske (`BelegPostenZeile.tsx`) und `BelegEinreichenPage`.                                                                                           |
| Immer eine leere Zeile    | Jede der drei Tabellen endet immer mit genau einer leeren Zeile; sobald darin etwas eingetragen ist, erscheint darunter die nächste leere Zeile. Buttons „Zeile hinzufügen“ entfallen in den Tabellen. Leere Zeilen werden nicht gespeichert, nicht validiert und haben kein Löschen-Icon. „Inhalt“: Ware = Ware gewählt; Kategorie = Artikel, Kategorie oder Preis; Leergut = Beschreibung oder Preis (vorbelegte Anzahl/Steuersatz zählen nicht). Enter in der letzten Zelle einer gefüllten Zeile springt in die nächste (leere) Zeile. Karten-Maske unter `md` und Mitglied behalten „Posten hinzufügen“.                       |
| Keine Nummern             | Spalte „Nr.“ entfällt. Meldungen nennen Tabelle und Zeile, z. B. „Waren, Zeile 2: Bitte wähle ein Gebinde.“ (Zeile = Position innerhalb der Art). Gilt für `belegPruefen` (`shared/src/belege.ts:540-548`), API (`finanzenBelege.ts:116`, `:203`), `belegFormular.ts:315/318` und die Zellfehler unter den Tabellen. Mitglied/Karten: „Posten N“ bleibt dort, wo die Karten nummeriert sind.                                                                                                                                                                                                                                        |
| Steuersatz ohne %         | Optionen in den Tabellen „19“, „7“, „0“, Spaltenkopf „Steuer %“ (das „%“ wurde nur in schmalen Spalten abgeschnitten).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| „davon Pfand“             | Darf nicht vom Löschen-Icon verdeckt werden (Betrag-Spalte breit genug, Text bricht innerhalb der Zelle um).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Rechnungssteller          | Neuer Beleg: kein Rechnungssteller vorbelegt (`useEffect` `FinanzenBelegPage.tsx:183-198` entfällt), das Feld hat initial den Fokus. Bei bestehendem Entwurf/eingereichtem Beleg kein Autofokus.                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Belegsumme                | Finanzer:in gibt oben die **Belegsumme (brutto)** an (nach Rechnungssteller/Datum). Buchen nur, wenn die Summe der Posten (inkl. Pfand, Leergut negativ) gleich ist. Neben/unter den Tabellen live: „Posten: X € · Belegsumme: Y € · Differenz: Z €“ (Differenz rot, wenn ≠ 0). Gespeichert im Entwurf-JSON (`belegsummeCent`); bei eingereichten Belegen mit `eingereichtBetragCent` vorbelegt. Pflicht und Prüfung in `belegPruefen` (also auch serverseitig).                                                                                                                                                                    |
| Summe ≤ 0                 | Prüfung „Die Summe des Belegs muss größer als 0 sein.“ (`belege.ts:406`) entfällt; Summe darf 0 oder negativ sein, bei **allen** Zahlwegen. Bar: Geldeingang in die Kasse (Stückelung positiv, Texte „Eingenommen“ statt „Ausgezahlt“ wo nötig). Bank: Eingang. Auslage Mitglied: negativer Betrag = Mitglied schuldet dem Verein. Mitglied darf beim Einreichen ebenfalls ≤ 0 angeben (`belegEinreichenSchema.betragCent`, `belege.ts:242`). `BELEG_BETRAG_WARNUNG_CENT` vergleicht den Betrag (`finanzenBelege.ts:264`).                                                                                                          |
| Sammelerstattung < 0      | Erlaubt (nur 0 ist ungültig, `finanzenBelege.ts:304`). Dann zahlt das Mitglied: Bar = Einlage in die Kasse (Stückelung positiv), Bank = Überweisung an den Verein. Offene Auslagen und Buch-Seite zeigen negative Salden verständlich („Mitglied schuldet …“).                                                                                                                                                                                                                                                                                                                                                                      |
| Leergut                   | Anzahl > 0 bedeutet **Rückgabe**; Preis = Pfand je Stück (≥ 0); Betrag = −Anzahl × Preis. Eigenständiger Pfand-Kauf kommt nicht vor (keine negative Anzahl). Gilt für Finanzer:in und Mitglied; Formulare zeigen den Betrag negativ.                                                                                                                                                                                                                                                                                                                                                                                                |
| Standard-Gebinde Pflicht  | Jede Ware hat ein Standard-Gebinde. Ware-Formular wählt automatisch das erste gewählte Gebinde vor, solange keins gesetzt ist; ohne Standard kein Speichern. Wird das Standard-Gebinde aus der Auswahl entfernt, muss ein neues gewählt werden (Vorbelegung wieder das erste). API: `standardGebindeId` Pflicht und muss zur Ware gehören (kein stilles Zurücksetzen mehr). Andere Stellen, die `ware_gebinde` ändern (falls vorhanden), setzen ein gültiges Standard-Gebinde. Ware-Detailseite (`WareDetailPage.tsx:125-131`): „(Standard)“ hinter dem Gebinde.                                                                    |
| Eindeutige Namen          | Namen und Aliase sind über **alle** Waren (auch archivierte) eindeutig, Vergleich ohne Groß/Klein und Leerzeichen am Rand; ein Alias darf keinem Namen einer anderen Ware gleichen und umgekehrt (innerhalb einer Ware gilt die bestehende Alias-Regel, und ein Alias gleich dem eigenen Namen ist ebenfalls unzulässig). Prüfung in `wareSpeichern` (`api/src/waren.ts`), Fehler „„X“ wird schon von der Ware „Y“ verwendet.“ am passenden Feld.                                                                                                                                                                                   |
| Neue Ware im Beleg        | Im Ware-Feld steht ganz unten immer „Neue Ware anlegen“ (mit Suchtext: „„Köstritzer“ als neue Ware anlegen“), nur mit Recht `waren:verwalten`. Öffnet `WareFormular` (Modal) mit vorbelegtem Namen; nach dem Speichern steht die neue Ware in der Zeile, samt Standard-Gebinde, Pfand und Kategorie/Steuersatz (über `warePatch`), Fokus auf Anzahl; `beleg-waren` wird neu geladen. Tabellen, Karten-Maske und Mitglied (dort nur mit dem Recht).                                                                                                                                                                                  |
| Artikel                   | Neue Tabelle `fin_artikel`: Name, normalisierter Name (eindeutig), Standard-Steuersatz. Ein Artikel entsteht beim **Buchen** eines Kategorie-Postens mit unbekanntem Namen, mit dessen Steuersatz. Wählt man im Formular einen bekannten Artikel, wird sein Standard-Steuersatz vorbelegt (vor dem Kategorie-Standard). Übersicht `/finanzen/artikel` (`finanzen:lesen`): Name, Standard-Steuersatz (änderbar mit `finanzen:buchen`), Kategorien mit Häufigkeit, Anzahl Posten, zuletzt gebucht. Kein Umbenennen/Zusammenführen (gebuchte Posten bleiben unverändert). Bestehende gebuchte Artikel werden per Migration übernommen. |

## Datenmodell

Migrationen ab der nächsten freien Nummer nach 0232, je mit Down-Datei, DSQL-Regeln aus `docs/datenbank.md` (eine Anweisung je Datei,
kein DROP COLUMN, Unique-Index `ASYNC`):

- `UPDATE waren SET standard_gebinde_id = (SELECT min(gebinde_id) FROM ware_gebinde wg WHERE wg.ware_id = waren.id) WHERE standard_gebinde_id IS NULL` (Spalte bleibt nullable, Pflicht prüft die API).
- `CREATE TABLE fin_artikel (id text PRIMARY KEY, name text NOT NULL, name_norm text NOT NULL, steuersatz … wie fin_belegposten, erstellt_am timestamptz NOT NULL, erstellt_von text NOT NULL)`; Unique-Index auf `name_norm`.
- Übernahme: `INSERT INTO fin_artikel … SELECT … FROM fin_belegposten WHERE art = 'kategorie'` gruppiert nach `lower(trim(text))` (Steuersatz/Datum des frühesten Postens, `erstellt_von = 'migration'`), nur nicht stornierte Belege.
- Leergut: gespeicherte Posten haben Anzahl und Preis positiv, der Betrag ist negativ (Berechnung, keine neue Spalte). Bestehende Dev-Leergut-Posten mit negativem Preis nicht migrieren (Regel „keine Altlogik vor Prod“); B-2026-0008 nicht anfassen.
- Belegsumme: nur im Entwurf-JSON (`fin_beleg_entwuerfe.daten`), gebucht zählt weiter `fin_belege.summe_cent`.
- Dev-Daten: vor dem Deploy doppelte Namen/Aliase auf dev bereinigen (bekannt: Alias „Sterni“ an Testbier und Sternburg Export → von Testbier entfernen).

## Shared

- `wareSchema`: `standardGebindeId` Pflicht (muss in `gebindeIds` oder deren Untergebinden liegen); `BelegWareDto.standardGebindeId: string`.
- Hilfsfunktion `wareNamenKonflikt(waren, kandidat)` (Name/Aliase normalisiert, liefert den Konflikt) für API und Formular-Vorprüfung, mit Tests.
- `postenBetrag`: Leergut = −round(anzahlMilli × einzelpreisCent / 1000); Leergut-Schema: Anzahl > 0, Preis ≥ 0.
- `belegBerechnen`: keine Prüfung Summe > 0. `belegPruefen`: Belegsumme Pflicht und gleich der Postensumme („Die Posten ergeben X €, die Belegsumme ist Y €.“); Meldungen „Waren/Kategorien/Leergut, Zeile N: …“.
- Entwurf-Schema: `belegsummeCent` (nullable im Entwurf). `belegEinreichenSchema.betragCent`: ganze Zahl im erlaubten Bereich, auch ≤ 0.
- Erstattung: Summe ≠ 0, Vorzeichen bestimmt die Richtung; Buchungszeilen mit Vorzeichen (`erstattungBuchungszeilen`, `belege.ts:502`).
- Artikel-DTOs: `ArtikelDto { id, name, steuersatz, kategorien: { kategorieId, anzahl }[], postenAnzahl, zuletztAm }`; `artikelVorschlaege` um `steuersatz` je Artikel erweitern.
- Bestehende Tests anpassen (`belege.test.ts:88` u. a.).

## API

- Waren: Standard-Gebinde Pflicht und gültig; Namens-/Alias-Eindeutigkeit mit Fehler am Feld; Tests.
- Belege: Leergut-Vorzeichen in `planeBeleg`/Buchungszeilen; Summe ≤ 0 bei allen Zahlwegen (Bar-Eingang, Bank, Auslage); Belegsumme-Prüfung; beim Buchen fehlende Artikel anlegen (in derselben Transaktion, Konflikt auf `name_norm` ignorieren); Tests.

- `GET /api/finanzen/artikel` (`finanzen:lesen`), `PATCH /api/finanzen/artikel/:id` `{ steuersatz }` (`finanzen:buchen`); `artikel-vorschlaege` und `einreichungen/auswahl` liefern den Standard-Steuersatz mit.
